# Smart Product Filter

افزونه فیلتر محصولات ووکامرس با AJAX

نویسنده: [احسان مهدی‌زاده](https://persiantik.net)

## تغییرات

### 1.2.5
- **رفع باگ:** `filter.js` مقدار `min_price`/`max_price` رو از همون ابتدا (با کمینه/بیشینه‌ی کل سایت) پر می‌کرد و توی *هر* درخواست AJAX (حتی صرف سورت یا فیلتر تاکسونومی، بدون دست زدن کاربر به اسلایدر قیمت) ارسال می‌کرد. چون سمت PHP با `BETWEEN` روی `_price` چک می‌شه، محصولاتی که اصلاً `_price` ندارن (مثلاً محصولات «تماس بگیرید») از نتیجه حذف می‌شدن. الان `min_price`/`max_price` فقط وقتی توی درخواست فرستاده می‌شه که کاربر واقعاً بازه رو از پیش‌فرض تغییر داده باشه.

### 1.2.4
- **رفع باگ طراحی مهم:** تنظیم `taxonomy_terms['product_cat']` هم‌زمان برای دو کار متفاوت استفاده می‌شد: (۱) انتخاب دسته‌های نمایش داده شده توی سایدبار فیلتر، و (۲) محدود کردن کل query محصولات توی همه‌ی آرشیوها به همون لیست. این باعث می‌شد هر دسته‌ای که از سایدبار تیکش برداشته می‌شد، محصولاتش توی آرشیو خودش هم دیگه نمایش داده نشه. این دو مورد الان کاملاً از هم جدا شدن؛ عدم انتخاب یک دسته در تنظیمات سایدبار، هیچ تأثیری روی نمایش محصولات آن دسته در آرشیو خودش ندارد.

### 1.2.3
- **رفع باگ:** بعد از انتخاب فیلتر/مرتب‌سازی/toggle از سایدبار، صفحه به بالای لیست محصولات اسکرول نمی‌شد (فقط کلیک روی pagination این کار رو می‌کرد). الان این اسکرول برای همه‌ی اکشن‌ها یکسان انجام می‌شه.
- استایل جدید pagination: باکس‌های گرد با بوردر `var(--gray1)`، و حالت فعال/هاور با بوردر و بک‌گراند `var(--primary)`.

### 1.2.2
- **رفع باگ مهم:** توی صفحه آرشیو یک تاکسونومی (مثلاً صفحه یک مدل خودرو)، هر اکشن AJAX (مرتب‌سازی، فیلتر، صفحه‌بندی، رنج قیمت، toggle ها) با «محصولی یافت نشد» مواجه می‌شد. علتش این بود که محدودسازی به آرشیو فعلی (فیچر نسخه ۱.۲.۰) از اسلاگ ترم به‌عنوان رشته متنی استفاده می‌کرد که توی رفت‌وبرگشت AJAX برای اسلاگ‌های فارسی مستعد خرابی encoding بود. الان از `term_id` (عدد، بدون هیچ مشکل encoding) استفاده می‌شه.

### 1.2.1
- **رفع باگ:** نمایش دسته‌های زیرمجموعه (و attribute های سلسله‌مراتبی) توی سایدبار خراب بود. `get_terms()` یه لیست مسطح و صرفاً الفبایی برمی‌گردونه (نه یه درخت مرتب بر اساس والد/فرزند)، و کد قبلی فرض می‌کرد ترتیب لیست همیشه «والد بلافاصله قبل از فرزندهاش» هست که همیشه درست نبود — مخصوصاً وقتی اسم زیرمجموعه (مثلاً یک مدل خودرو) با اسم والدش (کارخونه سازنده) شروع نمی‌شد. الان قبل از رندر، یه ساختار درختی واقعی از روی لیست مسطح ساخته می‌شه (به هر تعداد سطح که باشه)، و هر ترم دقیقاً زیر والد واقعی خودش قرار می‌گیره.

### 1.2.0
- **رفع باگ مهم:** فیلتر و مرتب‌سازی دیگه محدود به صفحه فعلی می‌شن، نه کل فروشگاه. مثلاً توی صفحه آرشیو یک برند خاص، «ارزان‌ترین» فقط محصولات همون برند رو مرتب می‌کنه.
- ترتیب نمایش تاکسونومی‌ها و attribute ها توی سایدبار الفبایی شد.
- مرتب‌سازی طبیعی (عددی-آگاه) برای ترم‌هایی مثل آمپر/وزن — دیگه «۹۰» قبل از «۷۰» نمیاد.
- رفع باگ: دکمه «حذف همه فیلترها» توی دسکتاپ اصلاً رندر نمی‌شد (هدر سایدبار جا افتاده بود).
- گزینه جدید ادمین برای هر تاکسونومی/attribute: «عدم نمایش این فیلتر در صفحه آرشیو خودش».
- توی صفحات آرشیو یک تاکسونومی (مثل صفحه یک برند)، سایر فیلترهای سایدبار فقط ترم‌هایی رو نشون می‌دن که توی همون آرشیو محصول دارن، و تعداد داخل پرانتز هم مخصوص همون آرشیوه.
- فیلتر جدید `spf_taxonomy_label` برای تغییر عنوان یک تاکسونومی توی سایدبار از طریق functions.php.
- نمایش تعداد نتایج کنار دکمه‌های مرتب‌سازی، با افکت شمارش هنگام تغییر فیلتر.

### 1.1.0
- رفع باگ Fatal Error (خطای 500) در صفحه تنظیمات ادمین: تابع رندر بازگشتی ترم‌ها داخل حلقه تعریف می‌شد و در سایت‌هایی با بیش از یک تاکسونومی پر (مثلاً هم `product_cat` هم `product_brand`) باعث «Cannot redeclare function» می‌شد. این تابع حالا به متد static داخل کلاس `SPF_Admin_Settings` منتقل شده.
- اطلاعات پلاگین (نویسنده، لینک) به‌روزرسانی شد.
- سه فیلتر toggle جدید در سایدبار اضافه شد: «فقط آیتم‌های موجود»، «فقط آیتم‌های تخفیف‌دار»، «فقط آیتم‌های ویژه» — هرکدام از طریق چک‌باکس جداگانه در تنظیمات ادمین قابل فعال/غیرفعال کردن هستند.

## منطق کلی

### ادمین
- تنظیمات توی `ووکامرس → فیلتر محصولات`
- انتخاب تاکسونومی‌ها و ترم‌های مجاز
- انتخاب attribute ها و مقادیر مجاز
- تعداد محصول در هر صفحه، نمایش فیلتر قیمت، نمایش تعداد
- نمایش/عدم نمایش سه فیلتر toggle: فقط موجود، فقط تخفیف‌دار، فقط ویژه

### فرانت‌اند
- بار اول صفحه با query پیش‌فرض لود میشه
- هر تغییر (sort، filter، pagination) با AJAX انجام میشه
- URL بروزرسانی میشه با query string
- موبایل: مودال Bootstrap از سمت راست باز میشه

### AJAX
- action: `spf_filter`
- nonce: `spf_nonce`
- پارامترها: `orderby`، `paged`، `min_price`، `max_price`، `filter_{tax_slug}[]`، `page_url`، `instock`، `onsale`، `featured`، `current_tax`، `current_term_id`

### toggle های سریع
- `instock`: فیلتر بر اساس `_stock_status = instock`
- `onsale`: فیلتر بر اساس خروجی `wc_get_product_ids_on_sale()`
- `featured`: فیلتر بر اساس تاکسونومی `product_visibility` (ترم `featured`)
- هرکدوم فقط وقتی توی سایدبار نمایش داده می‌شن که از تنظیمات ادمین فعال شده باشن

### فیلتر قیمت
- slider با jQuery UI
- دو input text (نه number) برای نمایش فرمت شده با کاما
- state واقعی توی `state.min_price` و `state.max_price` نگه داشته میشه

### رنگ‌ها
- کد رنگ از term meta با کلید `product_attribute_color` (افزونه Variation Swatches)
- تشخیص رنگ بودن با: `['color', 'colour', 'رنگ']`

### نکات مهم
- slug های فارسی encode میشن، همه جا `urldecode` میشن
- ترم‌های مجاز ادمین فقط توی سایدبار فیلتر میشن (نه روی query اصلی)
- `include_children` روی false — زیرمجموعه‌ها جداگانه انتخاب میشن
- ناموجودها همیشه آخر لیست

## Hooks (برای functions.php)

### تغییر عنوان یک تاکسونومی توی سایدبار
```php
add_filter('spf_taxonomy_label', fn($label, $slug) => $slug === 'product_cat' ? 'انتخاب خودرو' : $label, 10, 2);
```
`$slug` رو با اسلاگ تاکسونومی موردنظر عوض کن (مثلاً `pa_amp` برای یک attribute).
